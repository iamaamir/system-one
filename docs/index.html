01 / Architecture — System One

System One is
the abstraction.

Applications should depend on a capability, not a specific model. Jev, Reflex and future implementations expose the same bounded decision interface. system-one keeps application code independent from whichever provider performs the inference.

03 / Interop — Live boundary

Swap the provider.
Keep the application.

06 / Ecosystem — A primitive, not a framework

A primitive,
not a framework.

system-one-core ▲ ▲ │ │ │ │ pi-system-one pi-bifrost │ ▼ Pi

Pi exposes System One directly to agents. Pi-Bifrost consumes the same provider-neutral runtime for routing. Both depend on the primitive. Neither owns the abstraction.

07 / Batching — Shared state

One state.
Multiple decisions.

Multiple independent questions can be evaluated against the same state in a single System One request. This reduces duplicated context and keeps the decision surface explicit.

08 / Quickstart

Start in a few lines.

npm install system-one-core
import { SystemOne, HttpSystemOneProvider, choice } from "system-one-core";

const s1 = new SystemOne({ provider: new HttpSystemOneProvider({ baseUrl }) });
const { answer, confidence } = await s1.evaluate({
state,
questions: { team: choice("Which team?", { frontend: null, backend: null }) },
});
pi install npm:pi-system-one

export SYSTEM_ONE_BASE_URL=http://localhost:8008
